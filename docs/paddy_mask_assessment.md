# Paddy mask (PLANMalaysia polygons): method, results, limits

Generated by `pipeline/paddy_mask.py` and `pipeline/paddy_robustness.py`. The tables below are copied from `data/paddy_*.csv`; re-run the scripts to refresh them.

## Question
Does restricting the satellite features to mapped paddy (and to each granary's own scheme) improve the yield prediction and the transfer-learning result?

## Verdict
**QUALITY_CONTROL_ONLY.** The mask is worth keeping as a documented audit of the pixel sample. It does not improve yield accuracy on this data: no masked pixel set beat its
baseline with a 95% interval entirely below zero (the same gate the rest of the project uses before adopting a model), and the within-granary correlation between peak NDVI and yield
stayed between -0.05 and -0.03 under every mask.

## Method
1. **Polygon cleaning (polygons only).** Invalid geometry is repaired, zero-area slivers and fragments under 1 ha are dropped from the polygon layer. No pixel or satellite row is dropped.
2. **Pixel tagging.** Each pixel centre is intersected with the polygons. Overlaps are resolved as named scheme, then unnamed granary polygon, then non-granary polygon, then the larger polygon.
3. **Own scheme.** `geo/granary_scheme_map.csv` maps each granary to its scheme name(s). A granary not in the file is unknown, never "outside".
4. **Four pixel sets** (all pixels, on paddy, inside a granary scheme, own scheme only), granary-year features as the median across pixels (a granary-year needs at least 5 pixels in the set).
5. **Three tests:** (1) Spearman of feature with yield, pooled and within granary; (2) leave-one-year-out forecast = last year x (1 + ridge on the change in satellite features) against "same as last year";
   (3) leave-one-granary-out prediction of a new granary's yield level against the mean of the other granaries. Bootstrap intervals, 4,000 resamples, fixed seed.

## Limits
* The layer has no date or season field. It is one snapshot of unknown vintage, so it cannot describe change between years.
* The scheme labels look incomplete. KADA is labelled on only about 9,400 ha, 13 Pahang polygons in a granary carry no name, and the Seberang Perak and Pekan/Rompin mappings are assumptions. Verify with PLANMalaysia and the granary authorities before quoting `pct_in_own_scheme`.
* The sampled pixel grid is coarse relative to the polygons (median polygon about 0.7 ha), so a pixel centre on paddy does not mean the pixel is mostly paddy.
* This re-aggregates the existing extraction. It is not a new 10 m extraction over the polygons.
* One simple model per test, 70 granary-year labels, annual yield with the two seasons merged. A different model could differ, but with this label count the evidence for a different conclusion is weak.
* Peninsular Malaysia only: the layer has no Sabah or Sarawak polygons. A Sarawak paddy layer would be a separate file and a separate target domain.

## What would change the verdict
Better labels, not a better mask: season-level and block-level yield from KPKM and the granary authorities (`external/data_request_checklist.md`), then re-run `paddy_robustness.py`. If the within-granary correlation turns clearly positive
with the new labels, re-run this step before drawing conclusions about the mask.
